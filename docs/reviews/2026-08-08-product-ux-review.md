# 征收管理系统 — 产品与用户体验维度审查报告

> 审查日期: 2026-08-08
> 审查范围: web/app/ 全部页面路由与组件, web/prisma/schema.prisma 数据模型, SPEC-v1.2.2.md 及设计文档
> 审查人: 产品经理 (ecf24351ccea)

---

## 一、总体评估

系统已具备较完整的技术架构（46 页面、71 API 路由、31 客户端组件），覆盖了数据管理、审批流程、导出模板、H5 移动端、审计日志等核心模块。但在功能闭环、交互一致性、反馈机制和错误处理方面存在较多可改进项。

**整体成熟度**: M1（Schema/同步）约 80% 完成；M2（审批引擎）、M3（Word 模板）、M4（权限树/审计/H5）计划已编写但均未开始实现。当前系统处于 **部分功能可用但核心业务流程未闭环** 的状态。

---

## 二、按优先级排列的改进清单

### P0 — 阻断性问题（影响核心业务闭环）

#### 1. 审批流程状态筛选器无效
- **文件**: `web/app/dashboard/approval/approval-client.tsx:332`
- **问题**: 审批实例列表的状态筛选 `<Select>` 有 `defaultValue="all"` 但其值从未传递给 API，`loadInstances()` 始终获取全部实例。筛选器是纯装饰性的，误导用户。
- **影响**: 用户无法按状态筛选审批实例，在大量数据下无法定位待办项。
- **建议**: 将筛选值传入 API 查询参数，或在客户端做过滤。

#### 2. 审批实例"查看详情"按钮无功能
- **文件**: `web/app/dashboard/approval/approval-client.tsx:372`
- **问题**: "查看详情"按钮没有 `onClick` 处理函数，点击无响应。
- **影响**: 用户无法查看审批流程的详细进度、历史操作和 diff 信息。
- **建议**: 实现审批实例详情页面或弹窗，展示完整审批链、节点状态、操作记录和快照 diff。

#### 3. M2-M4 里程碑均未实现，核心业务链断裂
- **文件**: `docs/specs/plans/2026-08-08-v1.2.2-m2-approval-engine-designer.md`, `m3-word-excel-template-editor.md`, `m4-permission-audit-h5-e2e.md`
- **问题**: 三个里程碑计划文件中所有任务复选框均未勾选（`- [ ]`），意味着：
  - 审批引擎 v2（拖拽画布设计器、版本化发布、自动触发）未实现
  - Word 模板编辑器（A4 画布、字段库、docx 渲染）未实现
  - 四级权限树、审计中心 5 Tab、H5 全面改造未实现
- **影响**: 征收管理的核心流程（征收数据录入→审批→文档生成→审计）无法闭环运行。
- **建议**: 按 M2 → M3 → M4 顺序排期实现，M2 是当前最高优先级。

#### 4. 设计文档与 Schema 存在结构性差异
- **文件**: `docs/specs/2026-08-08-v1.2.2-levy-module-design.md` vs `web/prisma/schema.prisma`
- **差异清单**:
  | 维度 | 设计文档 | 实际 Schema |
  |------|---------|------------|
  | 新表 ID 类型 | String (cuid) | Int (autoincrement) |
  | 缺失表 | DocumentGenLog, LoginLog | 不存在（用 OperationLog 替代）|
  | 同步状态 | 6 态 (含 IN_APPROVAL, SYNCED) | 4 态 (PENDING/APPROVED/REJECTED/CANCELLED) |
  | 数据库 | PostgreSQL | MySQL |
  | 快照模型 | snapshotType 枚举 + module 字段 | changeType 字符串，无 module |
- **影响**: 后续开发（M2-M4）如果按设计文档编码会与现有 Schema 冲突。
- **建议**: 在 M2 开始前统一设计文档与 Schema，确定以 Schema 为准并更新设计文档。

### P1 — 高优先级（影响用户体验和效率）

#### 5. 全局缺少 Toast/通知反馈系统
- **涉及文件**: 几乎所有 client 组件（approval-client, data-list-client, audit-client, notifications-client 等）
- **问题**: 操作成功无反馈；操作失败使用 `alert()` 弹窗或仅 `console.error()`。
- **影响**: 用户无法感知操作是否成功，体验粗糙且不一致。
- **建议**: 引入统一的 Toast 组件（如 sonner 或 react-hot-toast），替换所有 `alert()` 和静默错误。

#### 6. 审批管理页面无加载状态
- **文件**: `web/app/dashboard/approval/approval-client.tsx`
- **问题**: 数据加载期间渲染空列表，用户看到空白页面闪烁。
- **影响**: 首屏体验差，用户可能误以为无数据。
- **建议**: 添加 Skeleton 或 Spinner 加载指示器。

#### 7. 通知中心缺少分页和完整的目标选择
- **文件**: `web/app/dashboard/notifications/notifications-client.tsx`
- **问题**:
  1. 固定 `pageSize=50`，无分页控件或"加载更多"
  2. 发布通知时角色列表硬编码（管理员/录入员/查看员 ID 1/2/3），未从 API 获取
  3. 目标类型为"指定用户"时，`targetUserIds` 字段无 UI 渲染
- **影响**: 通知功能无法正确用于实际场景。
- **建议**: 实现服务端分页、动态角色列表、用户选择器。

#### 8. Dashboard 布局无加载和错误状态
- **文件**: `web/app/dashboard/layout.tsx`
- **问题**: 服务端组件阻塞在 `getCurrentUser()` 和 Prisma 查询上，无 loading UI；数据库慢时用户看到空白页。无错误边界。
- **影响**: 首次加载体验差，异常时无降级 UI。
- **建议**: 添加 `<Suspense>` 包裹和 `error.tsx` 错误边界（已有 `dashboard/error.tsx` 但未覆盖 layout 层级的错误）。

#### 9. H5 移动端每次导航都重新查询徽章计数
- **文件**: `web/app/h5/(main)/layout.tsx`
- **问题**: 审批待办数和通知未读数在每次页面导航时串行查询数据库（未用 `Promise.all` 并行），无缓存策略。
- **影响**: 移动端页面切换延迟明显，影响流畅度。
- **建议**: 并行查询 + 短期缓存（如 30 秒内复用）。

#### 10. 数据列表搜索行为不一致
- **文件**: `web/app/dashboard/data/[tableName]/data-list-client.tsx`
- **问题**: `search` 状态不在 `useEffect` 依赖数组中，搜索仅在手动提交表单时触发。用户修改搜索词后翻页不会携带搜索条件（除非重新提交）。
- **影响**: 搜索结果与分页交互时可能丢失搜索条件，导致困惑。
- **建议**: 将搜索词加入 `useEffect` 依赖或翻页时自动携带当前搜索词。

### P2 — 中优先级（交互一致性和体验优化）

#### 11. 侧边栏缺少折叠/收起机制
- **文件**: `web/components/layout/sidebar.tsx`
- **问题**: 固定 256px 宽度，无折叠按钮；所有分区始终展开；表格多时侧边栏会很长。
- **影响**: 小屏桌面端空间利用率低。
- **建议**: 添加折叠/展开切换；分区支持收起。

#### 12. 侧边栏缺少退出登录入口
- **文件**: `web/components/layout/sidebar.tsx`
- **问题**: 底部显示用户信息但无退出按钮。
- **影响**: 用户需要找到其他位置退出，增加认知成本。
- **建议**: 在用户信息区域添加退出登录按钮。

#### 13. H5 底部导航缺少触摸反馈
- **文件**: `web/app/h5/(main)/bottom-nav.tsx`
- **问题**: Tab 切换无 `active:` 按压态样式、无过渡动画；导航栏 `fixed` 定位但无背景模糊，滚动内容穿透可见。
- **影响**: 移动端操作感不灵敏，视觉品质偏低。
- **建议**: 添加按压态样式、过渡动画和 `backdrop-blur` 背景。

#### 14. H5 审批操作后整页刷新
- **文件**: `web/app/h5/(main)/approval/approval-client.tsx`
- **问题**: 审批/驳回后调用 `location.reload()` 刷新整页。
- **影响**: 移动端整页刷新体验差，耗时长。
- **建议**: 操作成功后从列表中移除已处理项（乐观更新），或仅重新获取数据。

#### 15. H5 转办功能使用浏览器原生 `prompt()`
- **文件**: `web/app/h5/(main)/approval/approval-client.tsx`
- **问题**: 转办操作使用 `prompt()` 输入目标 userId。
- **影响**: 移动端原生弹窗体验差，且需要用户知道 userId 而非选择用户。
- **建议**: 实现用户选择器弹窗。

#### 16. 表单布局设计器缺少撤销/重做和拖拽分配
- **文件**: `web/components/form-layout-designer.tsx`
- **问题**: 无 undo/redo；字段只能逐个点击分配到单元格，无法拖拽；无键盘导航。
- **影响**: 管理员设计表单效率低，误操作无法回退。
- **建议**: 添加 Ctrl+Z 撤销栈；支持字段拖拽到单元格；添加方向键导航。

#### 17. 多处使用空 `catch {}` 静默吞掉错误
- **涉及文件**: `data-list-client.tsx:218`, `h5/data-list-client.tsx:189`, `h5/data-list-client.tsx:152`, `audit-client.tsx` 等
- **问题**: 空 catch 块导致错误被完全忽略，排查困难。
- **建议**: 至少 `console.warn` 记录，或通过 Toast 提示用户。

#### 18. 所有文档均未正式签批
- **涉及文件**: `SPEC-v1.2.2.md`, `docs/specs/2026-08-08-v1.2.2-levy-module-design.md`
- **问题**: 规格说明标记"v1.0-draft, pending approval"；设计文档签批区域为空白。
- **影响**: 需求基线未确认，开发可能基于未达成共识的方案。
- **建议**: 组织产品/技术/业务会签，确认需求基线后再推进 M2-M4。

#### 22. 审批流程管理缺少分页
- **文件**: `web/app/dashboard/approval/approval-client.tsx`
- **问题**: 工作流和实例列表均无分页。

#### 23. 侧边栏图标映射有限
- **文件**: `web/components/layout/sidebar.tsx`

## 四、用户流程断点分析

### 核心业务流程：征收数据管理全链路

```
征收数据录入 → 审批 → 文档生成 → 审计追踪
     ↓              ↓          ↓           ↓
   ✅ 可用      ⚠️ 半可用   ❌ 未实现    ⚠️ 部分可用
```

**断点 1**: 征收数据保存后应自动触发审批（SPEC G4），但自动触发机制（`LEVY_SAVE` trigger）属于 M2，未实现。
**断点 2**: 审批通过后需生成 Word 文档（协议、通知书等），但 Word 模板编辑器属于 M3，未实现。
**断点 3**: 征收变更需通知并同步到调查数据（SPEC G3），同步执行器属于 M2，未实现。

### 移动端核心流程

```
项目列表 → 数据列表 → 数据详情/新建 → 提交审批
    ✅         ✅          ✅            ⚠️ 仅基础
```

**断点**: H5 审批操作后整页刷新，转办使用原生 prompt，体验不连贯。
